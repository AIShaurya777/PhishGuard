What does a phishing detector actually look at?

Paste a link. Our model reads only its domain name, then shows which letters pushed it towards phishing and which towards legitimate.

This is a university course project trained on one public dataset. It can’t tell you whether a link is safe, and the section below explains why.

What we found

We trained models from logistic regression to neural networks on PhiUSIIL, a public dataset of 234,000 labelled links. The question changed as we went: from “how accurate can we get?” to “what has the model really learned?”

  1. On full links, every model looks near-perfect

    Models given the full link scored 99.7%, and 100.0% with all 50 of the dataset’s columns. But a one-line rule does almost as well: “if the link doesn’t start with https://www., call it phishing” is right 99.1% of the time. Every legitimate link in the dataset is a bare homepage like this. Only 2.4% of the phishing links are.

    Legitimate, all of them https://www.example.org
    Phishing, most of them http://secure-login.example.top/verify.php?id=7

    So the models learned how the dataset was collected, not what phishing looks like. To make the task honest, we removed the scheme, www. and the path, and kept only the domain.

  2. On the domain alone, the honest score is about 87%

    Test accuracy, averaged over five different splits. Each split keeps every site’s links together, so a model is never tested on a site it trained on.

    Our hybrid model, which reads the characters and 40 measured properties of the domain together, is the best on the domain alone. But its lead over plain character n-grams is small, under half a percentage point.

  3. On real websites, it raises false alarms and misses edited phishing

    We tested the saved models on about 25,000 popular websites that aren’t in the dataset, and on phishing domains changed in cheap ways an attacker could choose.

  4. The cause is the data, not the model

    The dataset’s legitimate side is a list of homepages, almost none with a subdomain. Its phishing side comes from feeds that over-represent some countries’ domains. A model can only learn the difference it’s shown, so it learned “subdomain means phishing” and “.ru means phishing”. A bigger model learns the same thing faster. The fix is legitimate data that looks like the real web.

    The labels add to it. All 782 google.com links in the dataset are labelled phishing: they are phishing pages hosted on Google Docs and Sites, and 7 are on accounts.google.com itself. A model that reads only the domain can’t tell those apart from Google’s real sign-in page.

    Independent audits of this dataset report the same shortcuts and the same false alarm on accounts.google.com. Our reference list cites them.

How it works

Data
PhiUSIIL (Prasad and Chandra, Computers & Security, 2024): 235,795 links, 234,204 after cleaning. 58% legitimate, 42% phishing.
Testing
70% train, 15% validation, 15% test. All links from the same site stay in the same part. Settings and the decision threshold are chosen on validation. The test part is scored once, on five different splits.
Models on this page
Hybrid: a character CNN reads the domain letter by letter, and its output is joined with 40 measured properties such as length, hyphens and number of subdomains. Character n-grams: logistic regression on every 1 to 4 letter chunk. Both were trained on the same split and never retrained for this site.
Explanations
For each letter, we blank it out and measure how much the hybrid’s score changes. For each property, we reset it to the average and do the same. We checked that this is faithful: on phishing domains the model caught, blanking the five most “phishing” letters flips the verdict for 20% of them, and blanking five random letters for 2.8%.
